# Native OpenCode ACP for Pica and plan nodes

Observed on 2026-10-16 with the installed OpenCode **1.18.34**. All local
protocol inspection used empty temporary homes, no credentials and **no
`session/prompt` or model invocation**. The browser functional check belongs to
Mokona. This is a capability record, not an automated test or harness.

| Capability              | Observed contract                                                                                                           | Pages handling                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Entry point             | `opencode acp`; native agent info `OpenCode`, `1.18.34`, protocol 1                                                         | Existing `AcpSession`, exact verified version; no external adapter. Internal HTTP server uses loopback, port 0 and a fresh process password.                       |
| Steering                | No `_meta.steering` announcement; `_session/steering` returns `-32601 Method not found`                                     | No steering request and no concurrent prompt. Visible `followUp` with its own turn; the UI explicitly says steering is unavailable.                                |
| Session configuration   | `session/new` returns select options `model` and `mode`; mode `pages-pica` was selected and confirmed without a model call  | Exact full provider/model ID and the managed mode must be offered and confirmed before a prompt.                                                                   |
| Variant                 | Release source exposes `effort` for models with variants; `default` resets it                                               | Exact stored variant; null explicitly resets to `default` when the selector exists. Not observed with a credentialed model.                                        |
| Content                 | Handshake advertises `embeddedContext` and `image`                                                                          | Shared Pica upload/type checks, immutable message payloads and visible transfer snapshots. Individual models may reject images.                                    |
| MCP                     | Handshake advertises HTTP and SSE                                                                                           | Only the existing `pages` HTTP bridge is supplied; job token goes over ACP stdin. Existing executor reauthorizes every call.                                       |
| MCP readiness           | Release source ignores registration failures; no verified local MCP-status command                                          | No fabricated readiness confirmation. The browser check must verify an actual authorized Pages tool call.                                                          |
| Native tools            | Managed permission rules deny `*` and allow only `pages_*`; custom Pica agent has the same rules                            | No native shell, filesystem, web, delegation or admin tool; unexpected ACP permission requests are refused. Tool execution remains subject to Pages authorization. |
| Resume / close          | Handshake advertises both; new → mode selection → close → resume → close succeeded locally without a prompt                 | Existing owner/chat/connection/model/variant/profile mapping and resource lifecycle. Closing a protocol session keeps its native archive.                          |
| Background continuation | Pica uses existing server-owned jobs and journals                                                                           | Browser close does not cancel. Explicit stop, deadlines and server shutdown cancel through the existing registry. No replay after restart.                         |
| Context                 | `usage_update.used` is the latest assistant call's input plus cache reads and writes. `size` is that model's context limit. | The runner journals the two fields with the selected model and attempt. The plan sidebar reads the latest snapshot for that attempt.                               |
| Tokens                  | Release source constructs prompt usage from the final assistant model step; cache and reasoning can contribute to total     | Persisted as partial counts, never presented as a complete tool-loop total.                                                                                        |
| Cost                    | Release source sums assistant costs over the native session                                                                 | Estimated session total; never a billed amount or a sum of repeated usage reports.                                                                                 |
| Deletion                | Protocol close does not delete the native archive                                                                           | Pages deletion reports its own scope; no claim that native/provider archives were erased.                                                                          |

The source audit uses the exact release, rather than the moving development
branch:

- [ACP service](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/acp/service.ts): initialization, session configuration, resume, close and MCP registration.
- [Configuration selectors](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/acp/config-option.ts): full model IDs, variants and the explicit default.
- [Usage](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/acp/usage.ts): last-step token report and cumulative session cost.
- [Content conversion](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/acp/content.ts): inline text resources and image blocks.
- [Configuration loading](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/config/config.ts) and [configuration paths](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/config/paths.ts): sources that must stay isolated or block startup.

Functional behavior with a real model, tool calls, image understanding,
compaction and cancellation has deliberately not been exercised by Codex.

## Plan path and credential audit

The inspection on 2026-10-16 ran only `opencode --version` (1.18.34),
read the installed `opencode-ai` binary and inspected the exact release source.
It started no ACP server, native agent, model request or live MCP process.
The protocol observations above are separate from the plan-path inspection.

| Area                  | Release evidence and Pages behavior                                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider identity     | The installed binary identifies `opencode` as OpenCode Zen with `OPENCODE_API_KEY` and the Zen endpoint. `openrouter` is a separate native provider. Console/Zen keys use `opencode`, never OpenRouter. A Z.AI Coding Plan key uses the native `zai-coding-plan` provider; such a connection lists and runs only that provider.                                                                                                                     |
| Credential format     | [Auth](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/auth/index.ts) accepts one `{type: "api", key: "…"}` entry per provider and reads `OPENCODE_AUTH_CONTENT` before `auth.json`. Pages encrypts newly saved native JSON with the existing connection-bound instance cipher and injects only the process environment. Legacy files retain their provider; explicit replacement encrypts the key and removes plaintext. |
| Catalog               | [Models command](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/cli/cmd/models.ts) lists the selected provider with full `provider/model` IDs and verbose metadata. Pages filters by the credential's provider, keeps exact IDs and derives variants only from `variants`. This does not verify account entitlement or balance.                                                                                          |
| Plan entry point      | Existing `OpenCodeAcpDriver`, `opencode acp --port 0 --hostname 127.0.0.1`. CLI version and ACP identity must both match 1.18.34. The former one-shot plan implementation is removed; model tests and unrelated text-only requests keep their separate existing CLI path.                                                                                                                                                                           |

Mode, full model ID and optional exact variant must be offered and confirmed before the prompt.                                                                                                                                            |
| Read only             | Native deny-by-default permissions allow reading and web tools, OpenCode's own task list `todowrite` (it changes nothing on the host) and the authorized Pages bridge. Shell, edits, tasks and other mutations are denied. Bubblewrap is mandatory and mounts the workspace read-only; the Pages credential grants only reading operations.                                                                                                         |
| YOLO                  | Native `*`: `allow`, with retained explicit environment-file read denials. No extra Pages tool allowlist. [Permission forwarding](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/acp/permission.ts) receives only native ask decisions; Pages approves offered allow options automatically. Native denies remain effective. Both modes retain the outer namespace and Pages authorization.                               |
| Native availability   | [Tool registry](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/tool/registry.ts) excludes the interactive question tool for the ACP client. Pages adds no question tool, external plugin or arbitrary MCP server. Native subagents and compaction use the same pinned model/variant; title and summary helpers stay disabled.                                                                                            |
| Prompt and acceptance | Resolved AGENT.md, resolved node instruction and parameters, asset delivery and the existing Pages contract travel through ACP. A Pages heading prevents native slash-command dispatch. Every OpenCode node needs accepted business progress, including a valid report, before successors start. Read-only ticket todos are reported without mutating Pages.                                                                                        |
| Reported model        | The confirmed ACP selector is recorded separately from the requested model. This release supplies no independent provider-response model identity. `modelVerification` records that limit; Pages never claims a separately observed model response.                                                                                                                                                                                                 |
| Errors                | [ACP service](https://github.com/anomalyco/opencode/blob/v1.18.34/packages/opencode/src/acp/service.ts) maps provider authentication to ACP auth-required and forwards other failures as service errors. Pages maps recognizable auth, balance/quota, model, rate and permission failures to stable codes; unknown messages remain generic and raw provider diagnostics are not persisted.                                                          |
| Cleanup               | Cancellation closes pending OpenCode ACP requests and terminates the process group and instance-tagged helpers. Native closeout, resource leases, connection mutation locks and workspace reservations require confirmed cleanup. No process is selected by executable name. Uncertain cleanup stays reserved for normal startup recovery.                                                                                                          |

Native MCP registration still ignores registration failures and exposes no
verified model-free readiness command. The plan run must not claim a connected
state on that basis. Credentialed tool execution, permissions in a real model
loop, native subagents, graceful exit and cancellation effects remain manual
functional acceptance work. The inspection added no automated tests or harnesses;
only existing assertions made obsolete by the changed OpenCode contract are
adjusted, without executing their suites.

## Step usage and work list while a turn runs

Observed on 2026-11-25 with OpenCode **1.19.6**. A request through the pilot
launcher ran `opencode run` with the free OpenRouter model
`openrouter/nvidia/nemotron-3.5-lightning:free`. Three jobs of the runner
script (`scripts/runner/opencode.mjs --acp`) ran over native ACP with the free
model `opencode/nemotron-3.5-lightning-free`, mode `pages-read-only`, in an
empty home without any credential and a folder of two text files. OpenCode Zen
had answered "Free usage limit reached" to `opencode/deepseek-v4.1-flash-free`
a few minutes before.

| Area                 | Observation and Pages handling                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native source        | The table `message` of `opencode.db` holds one row per model step of a session and of its sub-sessions. The database lies in `opencode/` below `XDG_DATA_HOME` of the process, without that variable below `.local/share` of its home. The session ID of `session/new` names its rows.                                                                                                                                                                                                                                       |
| When a step reports  | OpenCode writes the row when the step starts, with `tokens` `input`, `output`, `reasoning`, `cache.read` and `cache.write` at 0 and `cost` 0, and no `finish`. The end of the step replaces them with the measured counts, `tokens.total`, `cost` and `finish` (pilot: row at 2.3 s, counts at 4.2 s). The zeros of the start are no measurement: the step that Zen refused kept them for good. Pages reads such a row as a step that has reported nothing.                                                                  |
| Counting             | `tokens.total` is the sum of `input`, `output`, `reasoning`, `cache.read` and `cache.write` in every observed row, so the input leaves out the cache reads and the output leaves out the reasoning. Pages shows the reasoning within "Ausgabe", as the other providers count it, and the cache reads alone in "Cache".                                                                                                                                                                                                       |
| Answer of the prompt | `PromptResponse.usage` named the last model step only: of a turn of four steps with input 8,999, output and reasoning 781 and cache reads 12,672 it reported input 1,608, output 31, thought 365 and cache reads 4,224. `usage_update` came once, with the end of the turn.                                                                                                                                                                                                                                                  |
| Runner job           | From runner 1.25.4 the job reads the rows of its session every second while the prompt is open (`opencode-usage.mjs`), read only, and reports each finished step once as a `usage` event with the identity of its native message. A turn of seven steps reported six of them before it ended (after 3.0, 4.0, 4.0, 5.0, 6.0 and 7.0 s; the turn ended after 7.2 s). The rows that exist before the prompt belong to earlier prompts: a job that resumed that session reported its one new step and none of the seven before. |
| Pages host           | A plan session the Pages host runs itself reads the same rows through `OpenCodeSessionUsage.ts`. The path of the database and of the price list had not been handed to the session since the session start was restructured, so no row was read; `CliAcpSessionSetup.ts` names both again.                                                                                                                                                                                                                                   |
| Storage              | Both ways store a step in `agent_opencode_message_usage` under the ID of its native message, with the attempt that reported it first. A step that is reported again replaces its own counts, and a message another attempt owns is left as it is, so a repeated reading, the end of the turn and a later attempt never count twice. The counts of `PromptResponse.usage` stay in the turn row and are no part of the sums.                                                                                                   |
| Cost                 | `cost` of a step is what OpenCode calculated from its own model list. A runner step keeps it as the provider amount. A cost of 0 is a confirmed zero for a model its provider names free (`opencode/…-free`, `openrouter/…:free`): both free models reported 0 in every step. A cost of 0 for any other model is no amount, because OpenCode also calculates 0 without a price. A session on the Pages host prices as before: free model, OpenRouter price list, then the reported cost.                                     |
| Terminal sidebar     | The block "Verbrauch" of an OpenCode attempt shows the sums of its finished steps: "Eingabe", "Ausgabe", "Cache" and "Kosten". Before the first step ends every row is a dash; a reported 0 stays 0. While a turn runs the amount covers the finished steps and the hint says so. The hint names a provider amount, the zero of a free model or a catalog estimate. The context stays the separate reading of `usage_update`.                                                                                                |
| `todowrite`          | The adapter still sends no `plan` update: a call arrives as `tool_call` (title `todowrite`, kind `other`, empty input), `tool_call_update` `in_progress` with the list in `rawInput.todos`, and `completed` titled `N todos` with the list in `rawOutput.metadata.todos`. The runner job now records such a call as a `plan` event instead of tool lines, as the Pages host does, and sends a list one call repeats only once. Its read-only mode allows `todowrite` like "Lesend" of the Pages host.                        |
| Both list ways       | A list of `todowrite` and a list in the `plan` field of `update_step_progress` reach the same list of the attempt, one row per attempt with the entries numbered by position. The newer report replaces the list, so an entry never appears twice, and the terminal and the run bar read that one list. In the observed turn the first list arrived 0.6 s before the first file was read, and its entries went from in progress and open to done with each further call.                                                     |

Not observed: a step usage of a deployed Pages server in the browser, a fixed
agent node and a ticket node of a real plan run, a model with a price, and a
sub-session. The storage was run against an empty PostgreSQL 18 with the
journal events of the observed jobs, the sidebar was not opened.

this host, read only. It holds eight sessions of the native provider
`zai-coding-plan` of 2026-11-24, written by OpenCode **1.18.34** and
